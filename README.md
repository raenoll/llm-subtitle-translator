# LLM Subtitle Translator

用 **Gemini / OpenAI / Claude / Google Translate** 的 API 实时翻译 **Netflix、Disney+、Prime Video、YouTube、HBO Max、Apple TV+、TVer** 等流媒体的内置字幕。

## 工作原理

1. 内容脚本 (`content.js`) 注入到播放页面，每 200ms 轮询平台自身的字幕 DOM 节点。这里用轮询而不是 `MutationObserver`——多数播放器用 Shadow DOM 或 React 整块重建字幕节点，轮询更稳。
2. 同时 `inject.js` 在页面自身的 MAIN world 里挂上 `fetch` / `XMLHttpRequest`，拦截播放器请求的字幕文件（WebVTT / TTML / YouTube timedtext）。拿到整段字幕后可以**提前批量翻译**，播到时直接命中缓存，没有等待。
3. 字幕文本变化时，脚本把原文通过 `chrome.runtime.sendMessage` 发给 Service Worker。
4. Service Worker (`background.js`) 调用你配置好的后端（Gemini / OpenAI / Anthropic / Google Translate v2 / v3 / 自定义 OpenAI 兼容 endpoint）返回翻译，并清洗掉模型偶尔吐出的转义字符、代码围栏、HTML 实体等非译文内容。
5. 脚本把翻译后的文字叠在视频底部，并可选同时显示原文。
6. 本地缓存 + 最近上下文窗口：重复的同一条字幕不会重复消费 token；最近几行翻译会作为上下文传给模型，保持称谓、语气连贯。
7. 被识别为「不翻译的语言」的字幕直接放行显示原生字幕，不调用 API。

## 安装（加载为未打包扩展）

1. 打开 `chrome://extensions`
2. 右上角开启 **开发者模式 / Developer mode**
3. 点「加载已解压的扩展程序 / Load unpacked」，选择本目录 (`subtitle-translator/`)
4. 点扩展图标 → 打开「完整设置」
5. 选择 provider、填入 API Key、选目标语言
6. 点「测试连接」确认能返回翻译
7. 打开 Netflix / Disney+ 等，**先在平台里把原文字幕（例如英文）打开**，扩展就会自动接管

## 文件结构

| 文件 | 作用 |
|---|---|
| `manifest.json` | MV3 清单，声明权限与 content script 匹配站点 |
| `background.js` | Service Worker：所有 LLM API 调用、消息路由、默认设置 |
| `content.js` | 监听字幕 DOM、去重、缓存、请求翻译、渲染覆盖层 |
| `content.css` | 翻译覆盖层样式（大字 + 黑描边 + 半透明黑底，兼容全屏） |
| `inject.js` | 注入页面 MAIN world，拦截字幕文件请求以支持提前翻译 |
| `popup.html/js/css` | 点图标后的快速开关面板 |
| `options.html/js/css` | 完整设置页（API key / 模型选择 / 上下文 / 语言 / 译文样式 / 运行日志） |
| `icons/` | 16 / 48 / 128 px 占位图标 |

## 支持的平台

- Netflix（`.player-timedtext`）
- Disney+ / Hotstar
- Prime Video / Amazon Video
- YouTube
- HBO Max / Max
- Apple TV+
- TVer（video.js；部分节目是烧录字幕，无法抓取）

如果你发现某个平台不工作，多半是 DOM 选择器变了——编辑 `content.js` 里的 `PLATFORMS` 数组加上新的 `containerSelectors` 即可。

## 字幕样式

设置页「译文样式」里可以调：

| 选项 | 说明 |
|---|---|
| 字体 | 始终使用自己填的 CSS `font-family`，留空则用系统默认 |
| 字重 | 100–700，默认 400。实际可选档数取决于字体自身带几个字面——浏览器映射到最接近的真实字面，不会凭空合成。PingFang SC 有 6 个（最重 600，选 700 落回 600），Heiti SC 只有 2 个。原文行自动比译文轻一档 |
| 保留当前字号 | **开启**：字号沿用流媒体网站正在渲染的字幕大小，自动继承你在平台里设的字幕档位，并随播放器尺寸变化。**关闭**：使用下面自定义的字号 |
| 字号 | px 字号，以 1080p 为基准等比缩放；开启保留后由网站字号接管，此项置灰 |
| 当前网站字体 | 实时显示当前打开的流媒体标签页正在使用的字幕字体与字号，开关处于哪个状态都会显示 |
| 文字底 / 底色浓度 | 文字后面垫一层半透明黑底（默认 35%），亮画面下更易读；可关闭或调到 0–90% |

开启保留后若读不到字号（平台字幕关闭、或字幕烧录在画面里），自动回退到自定义字号。

**只继承字号、不继承字体**是有意为之：CSS 字体回退是逐字形进行的，而西方网站的字幕字体
（Netflix Sans、Roboto 等）不含中日韩字形，中文译文根本无法用它渲染，继承过来没有意义。
字号则与文种无关，继承后能直接沿用平台的字幕大小档位和播放器缩放。

## 译文语言

**规则：译文行只显示通过检查的译文。** 模型的回答如果是把原文照抄回来、用别的语言作答、或者什么都没返回，
这一句就不显示任何内容——绝不会把原文当作译文放上屏幕。

模型（尤其是速度快的轻量模型）出这类问题的常见情形：把台词当成对它说的话去"回答"、歌词和音效说明原样保留、
被安全过滤拦截而返回空内容。扩展的处理分三层：

1. **提示词**。写明目标语言的英文名和原名（如 `Simplified Chinese (简体中文)`）；说明输入是待翻译的台词，
   不是对模型说的话，不要回答、评论或拒绝；每次请求的用户消息开头也再写一遍目标语言
2. **逐条检查回答**（在后台完成，不合格的回答不会传到播放页）：
   - 与原文相同（忽略大小写、空格、标点）→ 判为原样返回
   - 目标是中文、日文、韩文、俄文、希腊文时，回答里没有目标文字 → 判为语言不对；目标是中文而回答里假名占比
     超过 15% → 判为答成了日文
   - 没有内容 → 判为空回答（被安全过滤拦截时会带上原因）
3. **重试**。不合格时立刻用更强硬的指令重问一次。仍不合格则这一轮作废，按 4 秒、30 秒的间隔再试，
   **最多三轮、共六次请求**，之后放弃。后两轮一上来就用强硬指令，并逐轮提高采样温度——低温下模型照抄过一次
   的句子，原样重问往往还是照抄

**不算错的情况**：

- 一两个词的人名或缩写被原样保留，如 `NASA.`、`Tom!`、`Mr. Smith`。会先重问一次，模型坚持保留就接受。
  `Thank you.`、`What?` 这类普通词句原样返回则不接受
- 纯汉字、读作中文也通的日文词（如「了解」）原样返回
- 繁体译简体时本来就没有差异的句子（如「你好」）
- 没有文字的行（`♪`、`……`、纯数字）直接原样显示，不发请求

**检查不到的情况**：目标语言是英文、西班牙文等拉丁字母语言时，无法低成本地区分英文和目标语言，只能查出
"整句原样返回"和"答成了中日韩文等其他文字"。目标语言是扩展不认识的自定义名称时，只检查原样返回。

## 不翻译的语言

字幕被识别为「不翻译的语言」列表里的语种时，扩展不调用 API，直接显示平台原本的字幕。

**中文和日文的区分。** 两者共用汉字，一行不含假名的字幕单看分不出是哪种。扩展按证据强弱依次判断：

1. **这一行来自的字幕文件**声明的语言（TTML 的 `xml:lang`，或 URL 里的 `lang=` / `….zh-Hant.vtt`）
2. **最近实际显示过的几行**：最近 3 行都没有假名 → 中文；最近 4 行里有 2 行以上带假名 → 日文；
   否则看最近 12 行里带假名的比例
3. 以上都没有时，按这一行本身判断（不含假名即视为中文）

字幕文件的语言只用来标记**它自己的台词**，不会改变整段会话的判断——播放器经常会预取你没选的字幕轨。
在同一个视频里切换字幕轨后，前 2 行可能仍按上一条轨判断，之后即跟上；若字幕文件自带语言声明则立即生效。

**列表写法不必完全一致。** 以下写法视为同一种：

| 语种 | 可用写法 |
|---|---|
| 繁体中文 | 繁體中文、繁体中文、繁中、正體中文、Traditional Chinese、zh-Hant、zh-TW、zh-HK |
| 简体中文 | 简体中文、簡體中文、简中、Simplified Chinese、zh-Hans、zh-CN |
| 两者都算 | 中文、Chinese、zh |
| 日文 | 日本語、日语、日文、Japanese、ja |

只写「简体中文」时，繁体中文字幕仍会被翻译成简体。

## 译文断句

字幕文件是按**原文**的行宽断行的（比如日文一行放 16 个字左右），模型翻译时又常照搬这个断法，
于是译文会在很别扭的位置换行。扩展在显示时会把译文重新排成一整行，超过画面宽度时才自然折行。

以下几种换行有实际含义，会**保留**：

| 情况 | 例子 |
|---|---|
| 句末标点之后（。！？ . ! ?，可带结束引号） | `好的。` ↵ `我们走吧` |
| 行尾破折号（话没说完） | `如果是提供伙食的话——` ↵ `也在预算之内` |
| 行首破折号（对话格式） | `- 是的` ↵ `- 不是` |
| 说话人标签开头（多人对话） | `啊……` ↵ `（杉山）是啊` |

省略号（……、...）不算句末。模型偶尔会丢掉行首的破折号或说话人标签，这时若原文行数相同，
会参考原文的结构来保留换行。只处理译文行，原文行保持原样。

## 运行日志 / 诊断

播放出问题时，保持播放页停在出问题的画面，到设置页「运行日志 / 诊断」点「刷新」。
不需要打开开发者工具，也不需要先打开「调试日志」开关。

顶部会给出结论，并把问题按责任方分开统计：

- **预翻译** —— 有多少句台词出现时译文已经备好，多少句需要现场翻译。预翻译库是空的、或多数句子来不及备好时会警告
- **模型** —— 首次回答不能用的次数，分为原样返回原文、答成别的语言、没有内容三类；其中多少次重问后挽回，
  多少次被扣下不显示，多少句稍后还会再试、多少句已放弃
- **请求** —— 网络错误、超时、接口报错的次数
- **插件** —— 按「不翻译的语言」直接显示了原字幕的句数，按语种列出。如果这里出现了你想翻译的语种，问题在该列表
- **原生字幕没有被隐藏** —— 译文下面还能看到平台自己的原文；会指出有几个字幕元素仍可见、其中几个在 shadow root 里
- **在显示译文却一个原生字幕元素都没匹配到** —— 该平台的字幕选择器可能已经过时
- **画面** —— 浏览器窗口、片源、视频元素和译文框各自的大小与位置。视频元素比可见范围大时（播放器裁切或放大画面时会这样），
  会注明其中有多大在可见范围内，译文按这部分定位；译文框有一部分落在可见画面之外时，顶部会给出 ❌

所以屏幕上出现原文时，看这里就能分清是哪一种：「插件」一行有数字说明是跳过列表；「原生字幕没有被隐藏」说明是隐藏失效；
两者都没有而「模型」一行有扣下的次数，说明模型出了问题但已被拦下，那一句应当是空白而不是原文。

## 成本提示

字幕一般每几秒变一次，长片可能产生上千次 API 调用。**强烈建议优先使用便宜的 flash / mini / haiku 级模型**：

- Gemini 2.5 Flash
- OpenAI gpt-4o-mini / gpt-4.1-mini
- Claude Haiku 4.5

扩展内部已做：
- 重复字幕缓存（500 条 LRU）
- 最近翻译作为上下文（避免每次都重新解释人物关系）
- 最小请求间隔节流

## 权限说明

- `storage`：保存你的 API key 和偏好（使用 `chrome.storage.sync`）
- `scripting` / `activeTab`：供内容脚本注入
- `host_permissions`：只匹配上述几个流媒体域名 + 对应 LLM API 域名

API key **只存在你本地的 Chrome sync storage 里**，不会上传到任何第三方服务器——请求直接从你的浏览器发到 LLM 提供商。

## 已知限制

- Disney+ 等用 Web Components 构建的播放器会把字幕放在 shadow root 里。普通的页面级 CSS 穿不过 shadow 边界，所以隐藏规则会被分别注入到每一个承载字幕的 shadow root 中，并在每个轮询周期重新确认（播放器换句时可能重建节点）。

- 部分平台（如 DRM 加密场景）可能把字幕绘制到 `<canvas>`，无法通过 DOM 抓取；此时扩展只能隐藏原生字幕，无翻译可显示。
- Apple TV+ 的字幕选择器最不稳定；如果遇到问题请用开发者工具找到真实的字幕类名并加进去。
- 翻译有 LLM 延迟（几百毫秒到 1 秒），快速对话场景下可能滞后。
